# Skill: File structure

Scaffold a new generated plugin as a **flat** Grasshopper project — the same shape as a project
created from the official Grasshopper template (no `src/` wrapper, project files at the root).

This skill creates the **folder tree and the non-code files**. The buildable Visual Studio project
itself — `.csproj`, `.sln`, `.csproj.user`, `Properties/launchSettings.json`, `[PluginName]Info.cs`,
`Properties/Resources.resx` + `Resources.Designer.cs` — is generated by the **`pr-vs-project`** skill,
which targets Rhino 7 + Rhino 8 (Win/Mac) and verifies the build. Run `pr-vs-project` as part of this
phase, then fill in the folders below.

---

## Target folder layout (flat)

```
[PluginName]/
├── spec/
│   └── session.json                   ← created in Phase 1 (intake)
├── demos/                             ← .gh demo files (Phase 12 Step B, pr-rhino-test; or demos/README.md if built by hand)
├── docs/                              ← portable markdown (pr-docs fills it, Phase 13)
├── [PluginName].Tests/               ← test project (pr-unit-tests fills it)
│   └── [PluginName].Tests.csproj
│
├── Components/
│   ├── [Subcategory]/                ← one folder per HTTP/JSON subcategory
│   └── Presets/                      ← GH_ValueList preset components live HERE
├── JSON Builders/                    ← [Resource]Builders.cs (note: space in folder name)
├── Utilities/
│   ├── [PluginName]Client.cs
│   ├── PluginUtilities.cs
│   └── ButtonComponent.cs
├── Icons/                            ← [XX]_*.png component icons + plugin icon
├── Properties/
│   ├── Resources.resx               ← (pr-vs-project)
│   ├── Resources.Designer.cs        ← (pr-vs-project)
│   └── launchSettings.json          ← (pr-vs-project) — Rhino 7 / Rhino 8 run profiles
│
├── [PluginName]Info.cs              ← (pr-vs-project) GH_AssemblyInfo + category icon
├── [PluginName].csproj             ← (pr-vs-project) multi-target Rh7/Rh8 Win/Rh8 Mac
├── [PluginName].csproj.user        ← (pr-vs-project)
├── [PluginName].sln                ← (pr-vs-project) references main + test project
├── icons.json                      ← (pr-icons) authored post-spec, NOT at scaffold time
├── manifest.yml                    ← (pr-yak-package, Phase 15) yak manifest; csproj copies it to bin/
├── README.md
├── LICENSE
├── CLAUDE.md
└── .gitignore
```

**No `assets/`, no `dist/` at scaffold time.** `bin/`, `obj/` (build) and `dist/` (`pr-yak-package`,
Phase 15) are created by the phases that produce them and are git-ignored; they are not
pre-scaffolded. `docs/` is kept and filled by `pr-docs` in Phase 13.

---

## Icons — not handled here

This skill does **not** generate the icon config. Icons are authored **after the spec is final** by
the `pr-icons` skill (which writes `icons.json` at the plugin root, lets the user specify every icon,
and renders via the pr-icon-generator MCP). Do not create `icons.json` at scaffold time —
just leave the `Icons/` folder empty for `pr-icons` to fill.

## .gitignore

Identical to the one `pr-gh-package` ships in Phase 14 (it re-emits the same list) — one source:

```
bin/
obj/
.vs/
*.user
dist/
*.DS_Store
.env
*.local
```

## Edge cases

- Plugin name has spaces or special chars: sanitise to PascalCase, warn user
  - "My Plugin!" → "MyPlugin" — tell the user the sanitised name before continuing
- Folder already exists: do not overwrite existing `.cs` files
  - Create missing folders only; skip files that already exist
  - Report which files were skipped
- The `JSON Builders` folder name contains a space — keep it exactly as-is for parity with the
  reference layout; do not rename to `JsonBuilders`
